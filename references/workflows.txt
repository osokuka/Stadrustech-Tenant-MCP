Hosted Tenant MCP — workflow string references (§17.3.2)
Source of truth for agents + FastMCP tool docstrings. Keep in sync with
workingscope/AI_FASTMCP_TOOLS.md and Stadrustech-Tenant-MCP docs/TOOLS.md.

--- tickets (tenant staff for any client) ---
Open: tickets_create · Assign: tickets_assign · Status: tickets_set_status ·
Priority: tickets_update(priority=…) · Comment: tickets_add_comment ·
List/detail: tickets_list / tickets_get · Comments: tickets_list_comments.

--- tickets.list “opened” (colloquial) ---
User says “any opened tickets” / “open tickets” / “what’s in progress or open”:
→ tickets_list(status="opened") [= unresolved|active|openish]
→ returns open + in_progress + pending (excludes resolved and closed).
Exact single status still: status=open|in_progress|pending|resolved|closed.
Optional client= after clients_resolve.

--- tickets.create ---
Gather: title (required), description (preferred), client UUID from clients_resolve
(preferred for SLA), priority (default medium), category (default incident),
optional location UUID, optional external_reference, service_rate_id from
clients_service_prices(client_id) (seeds billable_unit_price; optional
billable_unit_price override). Requires can_create_tickets. Status starts open; source=api.

--- tickets.set_status ---
status=open|in_progress|pending|resolved|closed.
pending REQUIRES comment (SLA pause). Prefer resolved then closed when finishing.
is_internal_note hides comment from client portal. Needs can_update_tickets.

--- tickets.priority ---
tickets_update(ticket_id, priority=low|medium|high|critical). Needs can_update_tickets.
May affect SLA targets — tickets_recalculate_sla if due dates look wrong.
Bulk: tickets_bulk(ticket_ids, priority=…) for many tickets.

--- tickets.comment ---
tickets_add_comment(ticket_id, content, is_internal_note=false).
is_internal_note=true → staff-only (hidden from client portal). Needs can_create_comments.
List with tickets_list_comments (needs can_read_comments).

--- tickets.assign ---
technician_id = Django user PK (= technicians[].user_id from
assignment_list_technicians). Sets status in_progress. Needs can_assign_tickets.
Do NOT pass TenantUser UUID.

--- assignment ---
assignment_recommend scores only; assignment_auto_assign assigns best match
(needs can_assign_tickets). Filter techs by role/location/city; include_workload=true
by default.

--- discovery ---
search(q, types=clients,projects,tickets,invoices) for mixed lookup.
clients_resolve(q) when the user names an organization.
clients_pack(client_id) — SUMMARY only (prices_included=false). Not for quotes.

--- service offers / exact prices ---
PRIMARY: clients_service_prices(client_id) — exact client EUR/h (`rate`) + id/code/name + TSV.
Alias: clients_offer_prices (same payload) — use when the user asks for offer pricing.
clients_service_catalog(client_id) — same priced lines (default limit=80; page via offset).
clients_services = alias of clients_service_catalog.
services_list(client=…) priced; services_list() with no client = summaries only.
services_get(id) for one line (+ clients using that SLA).
Never invent rates; quote `rate` for that TenantClient only.

--- retainers / recurring (tenant staff) ---
Do NOT use projects_create for monthly retainers or recurring payments.
1) clients_resolve → clients_service_prices(client_id)
2) Draft a document in the AI chat (scope, included hours, monthly amount)
3) Tell user to create the recurring charge in web: Billing → Recurring (pick client)
Clients may still create draft projects via Client MCP — that is fine.

--- projects (one-time / delivery only) ---
1) clients_resolve → clients_service_prices(client_id) [page if has_more]
2) projects_create(name, client=…) — do not invent default_hourly_rate; avoid billing_model=retainer
3) project_activities_create(project=…, service_rate_id=<catalog id>) REQUIRED
4) optional materials → projects_set_offer_validity → projects_offer_pdf|html|xlsx
Approve client-submitted: projects_approve(project_id) when status=submitted → planned.
Projects module must be enabled or tools return 403.
billing_model for delivery: time_and_materials|fixed_price.

--- activities / materials ---
project_activities_create REQUIRED: project UUID + service_rate_id from
clients_service_prices (catalog seeds name, default_hours, hourly_rate).
Optional name / estimated_hours / hourly_rate (staff override) / dates YYYY-MM-DD.
status planned→…→done. Materials: name, quantity, unit, unit_cost (staff can set costs).

--- invoices ---
Needs can_read_invoices. Filter by client UUID/name, billing_cycle, status,
billing_kind, settlement, search. invoices_pdf returns base64 PDF.

--- reports ---
reports_list → reports_schema(report_id) → reports_run(report_id, period|from/to,
optional client_id). clients.overview is tenant-staff only (not on Client MCP).

--- errors ---
401 missing/invalid key · 403 missing can_* / module off / wrong audience (ck_live_)
· 404 not in this tenant · 400 validation / no SLA / missing service_rate on activity
