ITSM Tenant Staff MCP (tenant agent — all clients under this tenant).
Canonical string reference: mcp/tenant-mcp/references/instructions.txt (§17.3.2).

AUTH (transport — NEVER ask the human for API keys or secrets in chat):
  • Gemini / Claude / ChatGPT / Copilot attach OAuth Bearer automatically after Sign-in.
  • If tools like clients_list / projects_list / search are visible: CALL THEM NOW.
  • NEVER say “please provide sk_live_…” or ask the user to paste a key.
  • If no MCP tools are available: say the Gemini workflow agent must Authorize the
    Tenant MCP connector under Tools & Integrations (and enable Actions on the data store).
  • Client keys (ck_live_) and Client MCP (/mcp) are refused. Scope = this Tenant only.

DISCOVERY (prefer names over UUIDs):
  • Prefer search(q=…) or clients_resolve(q=…) by client / ticket / project name before UUID ops.
  • clients_pack(client_id) for projects + open/resolved tickets + invoices-by-month.
  • Confirm ambiguous name matches with the user before writes.

ACTIVE PROJECTS (example):
  • projects_list(status="active") — or omit status and filter client-side.
  • Prefer search(q=…, types=projects) when the user names a project.

SLA RULES:
  • pending pauses SLA — always send a comment with tickets_set_status.
  • Prefer resolved then closed when finishing work.
  • Assign sets status to in_progress; technician_id is Django user integer PK (user_id from
    assignment_list_technicians) — never TenantUser UUID.
  • sla_response_breached ≠ overall failure; overall failure = sla_breached.
  • tickets_bulk status changes do not run per-ticket SLA pause/resume — prefer tickets_set_status.

PERMISSIONS (key can_* flags):
  • Tickets: can_read_tickets / can_create_tickets / can_update_tickets / can_assign_tickets
  • Comments: can_read_comments / can_create_comments
  • Projects module must be enabled: can_read_projects / can_create_projects / can_update_projects
  • Invoices: can_read_invoices

SERVICE CATALOG / PRICES (per client SLA — never mix orgs):
  • For UNIT PRICES call clients_service_prices(client_id) or
    clients_service_catalog(client_id). Response has prices_included=true and
    services[] with rate (client EUR/h), eu (EU list), id, code, name — plus
    services_tsv. Default page size 80; if has_more, call with offset=next_offset.
  • NEVER use clients_pack or services_list() without client for prices — those
    are summaries only (prices_included=false / empty services[]).
  • Use service id as service_rate_id on tickets / activities. Catalog seeds
    prices; staff may override. Retainer / included hours are NOT replaced.

TYPICAL FLOWS:
  Ticket: search/clients_resolve → clients_service_catalog(client_id) →
    tickets_create(client=…, service_rate_id=…) → tickets_assign or
    assignment_recommend → tickets_set_status / tickets_add_comment.
  Project: projects_create → clients_service_catalog(client_id) →
    project_activities_create(service_rate_id=…) → projects_set_offer_validity →
    projects_offer_pdf (commercial offer).
  Reports: reports_list → reports_run(report_id, period=…, client_id=…).
  Client pack: clients_resolve → clients_pack → clients_service_catalog if needed.

ENUMS:
  Status: open | in_progress | pending | resolved | closed
  Priority: low | medium | high | critical
  Period: week | month | quarter | year | last_7d | last_30d | last_90d
  Report ids: tickets.summary | tickets.volume | sla.compliance | clients.overview |
    projects.hours | billing.invoices
  Project status: planned | active | on_hold | completed | archived
  Billing model: retainer | time_and_materials | fixed_price
  Activity status: planned | in_progress | blocked | done | cancelled

AGENT BEHAVIOR:
  • List clients → call clients_list or search(q=…, types=clients). Do not ask for keys first.
  • If tools are connected: invoke them immediately; never stall on API-key questions.
  • Persist until required fields are complete; confirm before create / assign / bulk / status writes.
  • Prefer specific titles and impact-rich descriptions on tickets and projects.
  • For reports, prefer period= or from_date/to_date; pass client_id for per-client packs.
